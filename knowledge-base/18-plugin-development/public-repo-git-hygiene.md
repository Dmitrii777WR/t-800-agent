# Git-гигиена публичного репо

## Простыми словами

Типичный случай: разработчик публикует плагин на GitHub, а в истории коммитов остаются пути с именем пользователя машины и личный email. Публичная история индексируется и копируется — отозвать её потом почти невозможно. Дешевле не допустить утечки, чем лечить.

## 1. .gitignore для плагина

```gitignore
# Память и рантайм агента
t-800-memory/
runs/
telemetry/

# Секреты
.env
.env.*
!.env.example

# Системный мусор
.DS_Store
Thumbs.db

# Архивы и временное
*.zip
*.tar.gz
tmp/
```

## 2. Noreply email

GitHub выдаёт каждому пользователю noreply-адрес. Настройте его хотя бы для этого репозитория:

```bash
git config user.email "<owner>@users.noreply.github.com"
git config user.name "<owner>"
```

Проверка: `git config user.email` — там не должно быть личной почты.

## 3. Strip-secrets перед push

```bash
git grep -n -i -E "api[_-]?key|secret|token|password" -- . ':!.env.example'
rg -i "/Users/[a-z]+" --glob '!node_modules' .
```

Пустой вывод — чисто. Нашли совпадения — выносите значения в `.env`, добавляйте файл в `.gitignore`, примеры переписывайте на `<workspace>` / `<owner>` / `/tmp`.

## 4. Аудит истории

```bash
# Где строка появлялась во всей истории
git log -S "<строка>" --all --oneline

# Все авторы в истории
git log --format='%an <%ae>' | sort -u
```

В выводе авторов не должно быть личных email — только noreply.

## 5. Лечение истории

Если данные уже утекли в публичную историю:

- `git filter-repo` — переписывает историю: замена путей и email, удаление файлов целиком. После него обязателен force-push: `git push --force-with-lease origin main`
- Радикальная альтернатива — пересоздать репозиторий с чистой историей

Предупреждение: оба способа ломают clones и forks collaborators — им придётся переклонировать репозиторий, открытые PR могут потерять связь с историей. А то, что кто-то успел скопировать, не отозвать: утёкшие токены и пароли **меняйте**, чистка истории их не деактивирует.

## 6. Pre-push чеклист

1. `git status` — в коммите нет `.env`, памяти агента, архивов
2. `git config user.email` — noreply, не личная почта
3. `git grep` по секретам — чисто
4. `rg -i "/Users/[a-z]+"` — чисто (в примерах допустим только `/Users/user`)
5. `git log --format='%an <%ae>' | sort -u` — в истории нет личных email
6. `.gitignore` покрывает память, runs, `.DS_Store`, `.env`
7. Новые бинарники и архивы попали в коммит осознанно, а не случайно

## Частые ошибки

- Чистят только рабочую копию, а данные остаются в истории коммитов
- Force-push без `--force-with-lease` и без предупреждения collaborators
- Переписали историю, но не ротировали утёкшие секреты
