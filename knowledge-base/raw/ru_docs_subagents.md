# Субагенты

Субагенты — это специализированные AI-ассистенты, которым агент Cursor может делегировать задачи. Каждый субагент работает в собственном контекстном окне, обрабатывает определённые типы задач и возвращает результат родительскому агенту. Используйте субагентов, чтобы разбивать сложные задачи, выполнять работу параллельно и сохранять контекст в основной беседе.

Вы можете использовать субагентов в Редакторе, CLI и [Cloud Agents](https://cursor.com/docs/cloud-agent.md).

### Изоляция контекста

У каждого субагента есть собственное контекстное окно. Длительные исследовательские или поисковые задачи не занимают место в вашей основной беседе.

### Параллельное выполнение

Запускайте несколько субагентов одновременно. Работайте над разными частями вашей
кодовой базы, не дожидаясь последовательного завершения.

### Специализированная экспертиза

Настраивайте субагентов с пользовательскими промптами, доступом к инструментам и
моделями для задач в конкретных предметных областях.

### Повторное использование

Создавайте пользовательских субагентов и используйте их в разных проектах.

## Как работают субагенты

Когда Agent сталкивается со сложной задачей, он может автоматически запустить субагента. Субагент получает запрос со всем необходимым контекстом, работает автономно и возвращает итоговое сообщение с результатами.

Субагенты запускаются с пустым контекстом. Родительский агент включает релевантную информацию в запрос, так как субагенты не имеют доступа к предыдущей истории переписки.

### Передний план и фон

Субагенты работают в одном из двух режимов:

| Режим             | Поведение                                                                      | Лучше всего подходит для                           |
| :---------------- | :----------------------------------------------------------------------------- | :------------------------------------------------- |
| **Передний план** | Блокирует выполнение до завершения субагента. Немедленно возвращает результат. | Последовательных задач, где нужен результат.       |
| **Фон**           | Немедленно возвращает управление. Субагент работает независимо.                | Длительных задач или параллельных рабочих потоков. |

## Встроенные субагенты

Cursor включает три встроенных субагента, которые автоматически обрабатывают операции с большим объёмом контекста. Эти субагенты были разработаны на основе анализа диалогов агентов, в которых достигался лимит контекстного окна.

| Субагент    | Назначение                                | Почему это субагент                                                                                                                                                                 |
| :---------- | :---------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Explore** | Ищет и анализирует кодовые базы           | Исследование кодовой базы генерирует объёмный промежуточный вывод, который раздувает основной контекст. Использует более быструю модель для запуска множества параллельных поисков. |
| **Bash**    | Выполняет последовательности shell-команд | Вывод команд часто многословен. Его изоляция позволяет родительскому агенту сосредоточиться на принятии решений, а не на логах.                                                     |
| **Browser** | Управляет браузером через инструменты MCP | Взаимодействие с браузером создаёт шумные снимки DOM и скриншоты. Субагент отфильтровывает это до релевантных результатов.                                                          |

### Зачем нужны эти субагенты

У этих трёх операций есть общие черты: они создают шумный промежуточный вывод, выигрывают от специализированных промптов и инструментов и могут потреблять много контекста. Их запуск в виде субагентов решает сразу несколько проблем:

- **Изоляция контекста** — Промежуточный вывод остаётся внутри субагента. Родительский агент видит только итоговое резюме.
- **Гибкость выбора модели** — Субагент Explore по умолчанию использует более быструю модель. Это позволяет запускать 10 параллельных поисков за то же время, которое занял бы один поиск основным агентом.
- **Специализированная конфигурация** — У каждого субагента свои промпты и доступ к инструментам, настроенные под его конкретную задачу.
- **Экономия средств** — Более быстрые модели стоят дешевле. Изоляция токеноёмкой работы в субагентах с подходящим выбором моделей снижает общую стоимость.

Настраивать эти субагенты не нужно. Agent использует их автоматически, когда это уместно.

## Когда использовать субагентов

| Используйте субагентов, когда...                                | Используйте скиллы, когда...                                                                     |
| :-------------------------------------------------------------- | :----------------------------------------------------------------------------------------------- |
| Нужна изоляция контекста для длительных исследовательских задач | Задача узконаправленная и с одной целью (например, сгенерировать changelog, отформатировать код) |
| Вы запускаете несколько рабочих потоков параллельно             | Нужна быстрая, легко повторяемая операция                                                        |
| Задача требует специализированной экспертизы на многих шагах    | Задача выполняется за один шаг                                                                   |
| Нужна независимая проверка результата                           | Не требуется отдельный контекст                                                                  |

Если вы создаёте субагента для простой, узконаправленной задачи вроде «сгенерировать changelog» или «отформатировать импорты», лучше используйте [скилл](https://cursor.com/docs/skills.md).

## Быстрый старт

Agent автоматически использует субагентов, когда это уместно. Вы также можете создать пользовательского субагента, попросив Agent:

Create a subagent file at .cursor/agents/verifier.md with YAML frontmatter (name, description) followed by the prompt. The verifier subagent should validate completed work, check that implementations are functional, run tests, and report what passed vs what's incomplete.

Для большего контроля создавайте пользовательских субагентов вручную в каталоге проекта или в пользовательском каталоге.

## Пользовательские субагенты

Создавайте пользовательских субагентов, чтобы формализовать специализированные знания, обеспечивать соблюдение командных стандартов или автоматизировать повторяющиеся рабочие процессы.

### Расположение файлов

| Тип                            | Расположение        | Область действия                                               |
| :----------------------------- | :------------------ | :------------------------------------------------------------- |
| **Проектные субагенты**        | `.cursor/agents/`   | Только текущий проект                                          |
|                                | `.claude/agents/`   | Только текущий проект (совместимость с Claude)                 |
|                                | `.codex/agents/`    | Только текущий проект (совместимость с Codex)                  |
| **Пользовательские субагенты** | `~/.cursor/agents/` | Все проекты для текущего пользователя                          |
|                                | `~/.claude/agents/` | Все проекты для текущего пользователя (совместимость с Claude) |
|                                | `~/.codex/agents/`  | Все проекты для текущего пользователя (совместимость с Codex)  |

Проектные субагенты имеют приоритет при конфликте имён. Если в нескольких расположениях есть субагенты с одинаковым именем, приоритет у `.cursor/` над `.claude/` или `.codex/`.

### Формат файла

Каждый субагент — это markdown-файл с YAML-фронтматтером:

```markdown
---
name: security-auditor
description: Security specialist. Use when implementing auth, payments, or handling sensitive data.
model: inherit
readonly: true
---

You are a security expert auditing code for vulnerabilities.

When invoked:
1. Identify security-sensitive code paths
2. Check for common vulnerabilities (injection, XSS, auth bypass)
3. Verify secrets are not hardcoded
4. Review input validation and sanitization

Report findings by severity:
- Critical (must fix before deploy)
- High (fix soon)
- Medium (address when possible)
```

### Поля конфигурации

| Поле            | Тип     | Обязательно | По умолчанию           | Описание                                                                                                                                                    |
| :-------------- | :------ | :---------- | :--------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`          | string  | Нет         | Берётся из имени файла | Отображаемое имя и идентификатор. Используйте строчные буквы и дефисы.                                                                                      |
| `description`   | string  | Нет         | —                      | Краткое описание, которое показывается в подсказках инструмента Task. Agent читает его, чтобы решить, нужна ли делегация.                                   |
| `model`         | string  | Нет         | `inherit`              | Используемая модель: `inherit` или конкретный идентификатор модели. См. [конфигурацию модели](https://cursor.com/ru/docs/subagents.md#model-configuration). |
| `readonly`      | boolean | Нет         | `false`                | Если `true`, субагент запускается с ограниченными правами на запись (без редактирования файлов и shell-команд, изменяющих состояние).                       |
| `is_background` | boolean | Нет         | `false`                | Если `true`, субагент запускается в фоновом режиме и не блокирует родительский агент.                                                                       |

### Конфигурация модели

Поле `model` определяет, какую модель использует субагент. Есть два варианта:

| Значение                        | Поведение                                                                                                                                                                                      |
| :------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inherit`                       | Использует ту же модель, что и родительский агент. Это значение по умолчанию.                                                                                                                  |
| Конкретный идентификатор модели | Использует именно ту модель, которую вы указали, например `composer-2` или `gpt-5.6-sol`. Доступные идентификаторы см. в [справочнике моделей](https://cursor.com/docs/models-and-pricing.md). |

Выбирайте `inherit`, когда субагенту нужна та же способность к рассуждению, что и родительскому агенту. Используйте конкретный идентификатор модели, когда вам нужны возможности определённой модели независимо от того, что использует родительский агент.

#### Параметры модели

Добавьте к идентификатору модели квадратные скобки, чтобы задать параметры для конкретной модели, например speed, reasoning effort и контекстное окно. Записывайте параметры в виде пар `id=value`, а несколько параметров разделяйте запятыми.

| Пример                                    | Поведение                                                                            |
| :---------------------------------------- | :----------------------------------------------------------------------------------- |
| `composer-2.5[]`                          | Закрепляет базовую модель. Пустые скобки выбирают стандартный вариант, а не быстрый. |
| `composer-2.5[fast=false]`                | Явно выбирает стандартный (не быстрый) вариант.                                      |
| `claude-opus-5[effort=high]`              | Устанавливает для reasoning effort значение `high`.                                  |
| `claude-opus-5[context=300k]`             | Устанавливает контекстное окно размером 300k токенов.                                |
| `claude-opus-5[effort=high,context=300k]` | Комбинирует параметры.                                                               |

Доступные параметры зависят от модели и записываются в тех же парах `id=value`, что и в [параметрах модели](https://cursor.com/docs/sdk/typescript.md#model-parameters) SDK.

```markdown
---
name: planner
description: Plans complex changes before implementation.
model: claude-opus-5[effort=high]
---

Break the task into a clear, ordered implementation plan.
```

#### Когда настроенная модель не будет использоваться

Cursor учитывает поле `model` во фронтматтере вашего субагента, если не выполняется одно из следующих условий:

- **Ограничения администратора команды** — администратор вашей организации заблокировал указанную модель.
- **Устаревший параметр Max Mode** — на устаревшем тарифе с оплатой за запросы для этой модели нужен [Max Mode](https://cursor.com/help/ai-features/max-mode.md), а у вас он не включён.
- **Ограничения тарифа** — эта модель недоступна на вашем текущем тарифе.

В этих случаях Cursor переключается на совместимую модель. Если вы видите неожиданное поведение модели, проверьте настройки тарифа и модели.

```markdown
---
name: code-reviewer
description: Reviews code for correctness and style.
model: inherit
---

Review the code changes for bugs, style issues, and edge cases.
```

```markdown
---
name: search-agent
description: Searches the codebase for relevant files and symbols.
model: inherit
---

Search the codebase and return relevant file paths and code snippets.
```

```markdown
---
name: reasoning-agent
description: Handles complex architectural decisions.
model: gpt-5.6-sol
---

Analyze the architecture and recommend changes with detailed reasoning.
```

## Использование дочерних агентов

### Автоматическая делегация

Agent проактивно делегирует задачи на основе:

- Сложности и масштаба задачи
- Пользовательских описаний субагентов в вашем проекте
- Текущего контекста и доступных инструментов

Используйте фразы вроде "use proactively" или "always use for" в поле описания, чтобы поощрять автоматическую делегацию.

### Явный вызов

Запросите конкретного субагента, используя синтаксис `/name` в своем промпте:

```text
> /verifier confirm the auth flow is complete
> /debugger investigate this error
> /security-auditor review the payment module
```

Вы также можете вызывать субагентов, просто упоминая их в запросе:

```text
> Use the verifier subagent to confirm the auth flow is complete
> Have the debugger subagent investigate this error
> Run the security-auditor subagent on the payment module
```

### Параллельное выполнение

Запускайте несколько субагентов одновременно для максимальной пропускной способности:

```text
> Review the API changes and update the documentation in parallel
```

Agent отправляет несколько вызовов инструмента Task в одном сообщении, поэтому субагенты запускаются параллельно.

## Облачные субагенты

Из сессии локального агента можно передать задачу облачному субагенту, который работает в собственной VM и в собственной ветке. Ваше локальное рабочее пространство остается чистым и отзывчивым, пока длительные или параллельные задачи выполняются в облаке. Родительский агент продолжает работать локально или в облаке без прерывания. Облачные субагенты запускаются из [Окна Agents](https://cursor.com/docs/agent/agents-window.md) в десктопном приложении Cursor.

### Запустите облачный субагент с помощью /in-cloud

Введите `/in-cloud`, и следующая отправленная вами задача запустится как облачный субагент. Для работы над задачей он поднимет собственную VM и отдельную ветку.

Это удобно, чтобы изолировать долгие или параллельные задачи, например исправление CI, исследование проблемы или изучение кодовой базы, пока вы продолжаете работать локально.

### Сопровождение PR с /babysit

Поручите облачному субагенту следить за pull request с помощью `/babysit` или кнопки быстрого действия. Облачный агент удалённо вносит изменения, чтобы подготовить PR к слиянию, не занимая вашу локальную сессию.

Облачные субагенты используют [инфраструктуру](https://cursor.com/docs/cloud-agent/setup.md), настроенную для вашего репозитория, и следуют тем же правилам для модели и возможностей, что и другие [Cloud Agents](https://cursor.com/docs/cloud-agent.md). Поскольку они работают на облачной VM, их [MCP‑серверы](https://cursor.com/docs/cloud-agent/capabilities.md#mcp-tools) берутся из конфигурации вашей команды на [cursor.com/agents](https://cursor.com/agents), а не из вашей локальной сессии.

## Возобновление работы субагентов

Работу субагентов можно возобновлять, чтобы продолжать предыдущие беседы. Это полезно для длительных задач, которые охватывают несколько вызовов.

Каждый запуск субагента возвращает идентификатор агента. Передайте этот идентификатор, чтобы возобновить работу субагента с полным сохранением контекста:

```text
> Resume agent abc123 and analyze the remaining test failures
```

Фоновые субагенты по мере работы записывают своё состояние. После завершения вы можете возобновить субагент, чтобы продолжить беседу с сохранённым контекстом.

## Типовые паттерны

### Agent проверки

Agent проверки независимо подтверждает, была ли работа действительно выполнена, как заявлено. Это решает распространённую проблему, когда ИИ помечает задачи как выполненные, но реализации оказываются неполными или неработоспособными.

```markdown
---
name: verifier
description: Validates completed work. Use after tasks are marked done to confirm implementations are functional.
---

You are a skeptical validator. Your job is to verify that work claimed as complete actually works.

When invoked:
1. Identify what was claimed to be completed
2. Check that the implementation exists and is functional
3. Run relevant tests or verification steps
4. Look for edge cases that may have been missed

Be thorough and skeptical. Report:
- What was verified and passed
- What was claimed but incomplete or broken
- Specific issues that need to be addressed

Do not accept claims at face value. Test everything.
```

Создайте файл субагента по пути .cursor/agents/verifier.md с YAML-фронтматтером, содержащим name и description. Поле description должно быть: 'Validates completed work. Use after tasks are marked done to confirm implementations are functional.' Тело промпта должно предписывать ему быть скептичным, проверять, что реализации действительно работают, запуская тесты, и искать граничные случаи.

Этот паттерн полезен для:

- Проверки того, что функции работают end-to-end, прежде чем помечать задачи как завершённые
- Обнаружения частично реализованной функциональности
- Гарантии того, что тесты действительно проходят (а не просто что файлы тестов существуют)

### Шаблон оркестратора

Для сложных рабочих процессов родительский агент может последовательно координировать несколько специализированных субагентов:

1. **Planner** анализирует требования и создает технический план
2. **Implementer** реализует функциональность на основе плана
3. **Verifier** проверяет, что реализация соответствует требованиям

Каждый этап передачи включает структурированный вывод, чтобы следующий агент получал четкий контекст.

## Примеры субагентов

### Отладчик

```markdown
---
name: debugger
description: Debugging specialist for errors and test failures. Use when encountering issues.
---

You are an expert debugger specializing in root cause analysis.

When invoked:
1. Capture error message and stack trace
2. Identify reproduction steps
3. Isolate the failure location
4. Implement minimal fix
5. Verify solution works

For each issue, provide:
- Root cause explanation
- Evidence supporting the diagnosis
- Specific code fix
- Testing approach

Focus on fixing the underlying issue, not symptoms.
```

Создайте файл субагента по пути .cursor/agents/debugger.md с YAML-фронтматтером, содержащим поля name и description. Субагент debugger должен специализироваться на анализе первопричин: собирать стеки вызовов, определять шаги воспроизведения, изолировать сбои, вносить минимальные исправления и проверять работоспособность решения.

### Тестовый раннер

```markdown
---
name: test-runner
description: Test automation expert. Use proactively to run tests and fix failures.
---

You are a test automation expert.

When you see code changes, proactively run appropriate tests.

If tests fail:
1. Analyze the failure output
2. Identify the root cause
3. Fix the issue while preserving test intent
4. Re-run to verify

Report test results with:
- Number of tests passed/failed
- Summary of any failures
- Changes made to fix issues
```

Создайте файл субагента .cursor/agents/test-runner.md с YAML-фронтматтером, содержащим поля name и description (с упоминанием 'Use proactively'). Субагент test-runner должен проактивно запускать тесты при обнаружении изменений в коде, анализировать их падения, исправлять проблемы, сохраняя замысел тестов, и сообщать о результатах.

## Рекомендации

- **Создавайте узкоспециализированные субагенты** — у каждого субагента должна быть одна чёткая зона ответственности. Избегайте универсальных «helper»-агентов.
- **Тщательно прорабатывайте описания** — поле `description` определяет, когда Agent делегирует задачу вашему субагенту. Потратьте время на его доработку и уточнение. Тестируйте, формулируя промпты и проверяя, тот ли субагент срабатывает.
- **Делайте промпты лаконичными** — длинные, растянутые промпты рассеивают фокус. Формулируйте их конкретно и прямо.
- **Добавьте субагентов в систему контроля версий** — закоммитьте `.cursor/agents/` в репозиторий, чтобы ими могла пользоваться вся команда.
- **Начинайте с агентов, сгенерированных с помощью Agent** — позвольте Agent помочь с черновой конфигурацией, затем доработайте её под свои задачи.
- **Используйте hooks для файлового вывода** — если вам нужно, чтобы субагенты создавали структурированные файлы, рассмотрите использование [hooks](https://cursor.com/docs/hooks.md) для их обработки и единообразного сохранения.

### Антипаттерны, которых следует избегать

**Не создавайте десятки общих субагентов.** Наличие 50+ субагентов с расплывчатыми
инструкциями вроде "помогает с кодом" неэффективно. Agent не будет понимать, когда их
использовать, а вы будете тратить время на их поддержку.

- **Расплывчатые описания** — "Использовать для общих задач" не даёт Agent сигнала, когда делегировать задачу. Будьте конкретнее: "Использовать при реализации потоков аутентификации с провайдерами OAuth."
- **Слишком длинные промпты** — промпт на 2 000 слов не делает субагента умнее. Он делает его медленнее и сложнее в обслуживании.
- **Дублирование slash-команд** — если задача узкоспециализированная и не требует изоляции контекста, вместо этого используйте [навык](https://cursor.com/docs/skills.md) или [команду](https://cursor.com/docs/customize-cursor.md#extension-components).
- **Слишком много субагентов** — начните с 2–3 узконаправленных субагентов. Добавляйте ещё только тогда, когда появляются чёткие, различимые сценарии использования.

## Управление субагентами

### Создание субагентов

Самый простой способ создать субагента — попросить Agent создать его за вас:

Create a subagent file at .cursor/agents/security-reviewer.md with YAML frontmatter containing name and description. The security-reviewer subagent should check code for common vulnerabilities like injection, XSS, and hardcoded secrets.

Вы также можете создавать субагентов вручную, добавляя markdown-файлы в `.cursor/agents/` (проект) или `~/.cursor/agents/` (пользователь).

### Просмотр субагентов

Agent включает всех пользовательских субагентов в свои доступные инструменты. Вы можете увидеть, какие субагенты настроены, заглянув в каталог `.cursor/agents/` вашего проекта.

## Производительность и стоимость

У субагентов есть свои плюсы и минусы. Понимание этого помогает решить, когда их использовать.

| Преимущество            | Компромисс                                                                   |
| :---------------------- | :--------------------------------------------------------------------------- |
| Изоляция контекста      | Накладные расходы на запуск (каждый субагент собирает свой контекст)         |
| Параллельное выполнение | Более высокий расход токенов (несколько контекстов выполняются одновременно) |
| Узкая специализация     | Задержка (может быть медленнее основного агента для простых задач)           |

### Учёт токенов и стоимости

- **Субагенты потребляют токены независимо** — У каждого субагента своё контекстное окно и собственный расход токенов. Запуск пяти субагентов параллельно использует примерно в пять раз больше токенов, чем один агент.
- **Оценивайте накладные расходы** — Для быстрых и простых задач основной агент часто работает быстрее. Субагенты лучше подходят для сложной, долгой или параллельной работы.
- **Субагенты могут быть медленнее** — Их преимущество — изоляция контекста, а не скорость. Субагент, выполняющий простую задачу, может быть медленнее основного агента, поскольку каждый раз начинает с нуля.

## FAQ

### Какие встроенные субагенты доступны?

Cursor включает три встроенных субагента: `explore` для поиска по кодовой базе, `bash` для выполнения shell-команд и `browser` для автоматизации браузера через MCP. Они автоматически обрабатывают операции, требующие большого контекста. Вам не нужно их настраивать.

### Могут ли субагенты запускать другие субагенты?

Да, в пределах ограничения по вложенности. Начиная с Cursor 2.5, субагенты могут запускать дочерние субагенты, создавая дерево
скоординированной работы. Основной агент и его прямые субагенты могут запускать субагенты, но субагент, запущенный другим субагентом, не может запускать новые.
Для вложенных запусков также требуется доступ к инструменту Task в текущем
режиме, а хуки или политики инструментов могут блокировать запуск.

### Как узнать, что делает субагент?

Фоновые субагенты записывают вывод в `~/.cursor/subagents/`. Родительский агент
может читать эти файлы, чтобы отслеживать прогресс.

### Что происходит, если субагент завершился с ошибкой?

Субагент возвращает статус ошибки родительскому агенту. Родитель может
повторить попытку, возобновить выполнение с дополнительным контекстом или обработать сбой другим способом.

### Могу ли я использовать инструменты MCP в субагентах?

Да. Субагенты наследуют все инструменты родительского агента, включая инструменты MCP с
настроенных серверов. [Облачные субагенты](https://cursor.com/ru/docs/subagents.md#cloud-subagents) — исключение: они работают на облачной VM и используют MCP‑серверы, настроенные для вашей команды на [cursor.com/agents](https://cursor.com/agents), а не серверы из вашей локальной сессии.

### Как отладить неправильно работающий субагент?

Проверьте описание и промпт субагента. Убедитесь, что инструкции
конкретные и однозначные. Вы также можете протестировать субагента, явно вызвав его
с простой задачей.

### Почему мой субагент использует другую модель?

Cursor переопределяет настроенную модель, если администратор вашей команды её блокирует, ваш тариф её не включает или устаревший тариф с оплатой за запросы требует [Max Mode](https://cursor.com/help/ai-features/max-mode.md), а у вас он не включён. В устаревших тарифах с оплатой за запросы без Max Mode субагенты запускаются с использованием Composer независимо от конфигурации `model`. Если администратор вашей команды заблокировал Composer, субагенты могут запускаться только при включённом Max Mode. В тарифах с оплатой по использованию и в устаревших тарифах с оплатой за запросы с Max Mode субагенты по умолчанию используют модель родительского агента. Подробности см. в разделе [конфигурация модели](https://cursor.com/ru/docs/subagents.md#model-configuration).
